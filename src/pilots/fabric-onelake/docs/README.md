# FinOps Fabric / OneLake pilot developer documentation

This is the design and review guide for the bounded supplied-Parquet experiment.
The [pilot README](../README.md) records purpose, authorization, alternatives, source
acceptance, setup, mandatory validation, and graduation. It is self-contained; private
analysis and correspondence are not implementation dependencies.

## Design decisions

1. **Upstream owns normalization.** Reuse canonical
   `src/open-data/dataset-metadata/FocusCost_1.2-preview.json` and its integrity pin.
   Validate supplied normalized Parquet rather than reimplement business semantics
   in Spark. Actual export schema/stage/casts and remaining KQL enrichment are unknown;
   metadata or a Kusto declaration does not establish interoperability.
2. **Managed Delta is an optional independent serving copy.** It permits pilot-owned
   lifecycle and layout experiments without changing RTI or managed OneLake files.
   It is not proof of better performance than shortcuts or system-managed layouts.
   Evaluate supported RTI and Eventhouse OneLake access first.
3. **Replace accepted complete months, never accumulate snapshots.** Delta
   `replaceWhere` addresses target replacement, not upstream completeness. The
   ingestion manifest and row-conservation checks only establish the rows actually
   read survive staging/writing. The aggregate shrink floor is heuristic, not proof
   of every intended month/scope. Use the operator's
   [pre-write acceptance procedure](../README.md#input-acceptance-and-coexistence-boundary)
   to refuse incomplete, stale, ambiguous, or zero-row replacements and serialize
   manual and orchestrated writers. Notebook 02 requires a nonempty
   `acceptance_record_id` alongside `ingestion_id` and endpoint parameters. This
   references the independent coverage/order/exclusive-writer decision and is printed,
   not verified or persisted in an additional ledger column. The operator retains the
   durable record; the parameter does not automate source validation or locking.
   Notebook 02 sets the Spark session time zone to UTC before deriving `x_ChargeMonth`
   from `ChargePeriodStart`; replacement uses UTC calendar months, not the caller's
   local month boundary.
4. **Prove the manual path before advertising automation.** Manual Fabric validation
   is selected but not yet executed. Optional REST get-or-create provisioning and
   the single-notebook ADF runner are live-unvalidated. The runner does not provision
   the complete ingestion/write/maintenance chain or a core hub deployment condition.
   API-blocked environments have no implied ADF fallback.
5. **SQL/report compatibility before separately scoped Direct Lake adoption.**
   Preferred source fragments retain the existing Import partition; optional
   whole-partition replacement is DirectQuery. Neither is a Direct Lake model.
   A successful swap does not remove Import constraints or establish scale/economics.

### Numeric policy and compatibility

The explicit operator decision is exact `decimal(38,18)` for **all canonical logical
Decimal fields**. Accept only decimal inputs with values representable without
rounding or overflow; reject double, float, string, and integer input types for those
fields. Storage acceptance tolerance is **zero**. Derive the complete Decimal field
set from pinned canonical metadata; logical Number remains finite `double`.
Canonical metadata, its integrity pin, and nullability remain unchanged; neither a
Kusto type nor a synthetic fixture establishes the schema of an actual export.

Validate decimal values before target mutation, including larger source scales that
fit exactly and those that would require rounding, magnitude overflow, fractions,
credits, and nullable values. Verify every applicable field's persisted type and
exact value through ingestion/staging/write, not only financial aggregate totals.
The helper casts accepted exact values to `decimal(38,18)` before staging and
revalidates before writing. The target guard rejects incompatible existing canonical
numeric columns before writing and preserves original data. No target rebuild,
destructive migration, or silent target conversion is authorized.

Actual upstream schema and SQL/report execution evidence remain absent. Consumer
reconciliation must separately establish the observed SQL and Power BI representation
and any justified consumer-boundary tolerance; it cannot weaken exact storage acceptance.
[The documented SQL analytics endpoint mapping](https://learn.microsoft.com/fabric/data-warehouse/data-types#autogenerated-data-types-in-the-sql-analytics-endpoint)
is Delta DECIMAL → SQL `decimal(p,s)` (inspected September 21, 2026), not evidence
that the selected endpoint or semantic model has been exercised.

## What the checks establish

| Check | Boundary and limitation |
| --- | --- |
| Schema, non-null, version, and canonical integrity | Standalone declared acceptance, not proof of the actual upstream handoff. |
| Source/staging row conservation and staging manifest | Conservation of observed input, not independent coverage. |
| Month replacement, replay, and shrink heuristic | Correct replacement needs accepted full snapshots and single-writer isolation; missing scope/month can still pass the heuristic. |
| Active-snapshot compaction metrics | Intersect listing with active Delta files; superseded files awaiting VACUUM must not inflate counts. Actual operation metrics distinguish bytes rewritten from total table size. |
| Deployment preflight | Parameter/endpoint checks and explicit unsupported-private-networking rejection, not proof of connectivity, permissions, tenant support, or successful execution. |
| Notebook 04 | Point-in-time listed checks only; no historical promotion verdict, semantic-model test, or Direct Lake authorization. |

Preserve existing failure behavior and active-file metric semantics while correcting
claims. Permission, service, and evidence-read errors must not become empty-success
fallbacks. Review evidence selection by target identity before latest timestamp,
malformed/future/offset timestamps and the 26-hour boundary, equivalent/conflicting
latest ties, missing evidence, and compatible/unsupported local identities.

## Provisional physical policy

Logical charge-month replacement, physical `x_ChargeMonth` partitioning, and aggregation
are separate decisions. Retain current physical layout during correctness work unless
a specific incompatibility requires an explicit policy/test decision.

Current 128 MB target / 64–256 MB range, Z-order keys, daily compaction, average-size
floor, and small-file thresholds are unvalidated tuning choices. Neither these nor the
historical 256 MB–1 GB proposal are universal Direct Lake eligibility requirements.
The 26-hour age check is a daily interval plus two hours lateness, not a missed daily
run. The operator must establish schedules/alerts; no cadence is provisioned here.

[Current maintenance guidance](https://learn.microsoft.com/fabric/fundamentals/table-maintenance-optimization)
recommends runtime-aware adaptive sizing/auto-compaction, justified partitioning, and
measured clustering predicates. Record runtime and inherited/explicit settings,
including optimize-write, auto-compaction, adaptive sizing, V-Order, clustering, and
table features; mark unknowns unknown. Do not automatically upgrade runtime or adopt
liquid clustering/deletion vectors in this correction. New V-Order configuration,
existing-file retrofit, and file-level verification are deferred. Observing a runtime
setting is not verifying existing files.

## Diagnostic compatibility

Retain `_pilot_ingestion_metrics` and `_pilot_compaction_metrics` as operational data.
Notebook 04 appends listed-check output to `_pilot_directlake_gate`:

- `checks` remains boolean-only; `reasons` remains failure-only.
- A separate `assessmentMetadata` object contains
  `assessmentScope: "listedChecksOnly"` and `vOrderVerification: "notPerformed"`.
- Persist that object as JSON in one nullable STRING column named
  `assessmentMetadata`; new rows populate it. Evolve only that compatible addition
  on an existing table using append-scoped additive `mergeSchema`, not a session-wide
  evolution setting. Incompatible schemas fail; no broad schema auto-merge,
  dropping/recreating the table, or destructive migration is intended.
- Preserve old rows; missing legacy metadata means **unknown**, not equivalent to
  the new assessment. Passing means only the listed checks passed.

The supported evidence identity boundary is an **unqualified simple Lakehouse-local
table identifier**. The adapter uses `spark.sql.caseSensitive` with
`catalog.listTables()` / `catalog.getTable()` consistency checks and an alternate-case
`tableExists()` / `getTable()` probe to reject catalog/analyzer disagreement. It uses
**Spark catalog case semantics, verified against catalog resolution; unsupported
ambiguity is rejected**, then filters evidence using exact or lowercase equality as
appropriate **before collecting rows**. Do not guess case behavior, strip qualifiers,
or equate qualified/cross-Lakehouse aliases. Unsupported identifiers or
ambiguous/conflicting latest evidence must fail explicitly.
Select evidence for the target table before choosing the latest UTC instant; reject
malformed or future timestamps and missing evidence. Engine and real Fabric adapter
validation are still required; these boundaries are not evidence of completed tests.

Notebook 05 and promotion/history, optional query-filter reading, and telemetry
Z-order recommendation APIs are withdrawn, with no replacement reporter. Existing
`_pilot_directlake_promotion` or `_pilot_query_filter_stats` data is not deleted.
Stop scheduling the retired notebook; no supported reader or automatic historical
trust upgrade is provided. Old/mixed diagnostic records require independently
reviewed provenance before any billing-cycle or graduation assessment.

## Testing and validation

No historical test counts are offered as evidence for the corrected code.
Run the existing pilot suite and the actual Spark/Delta module using the repository's
documented environment and `requirements-dev.txt`; CI is
`.github/workflows/pilot-fabric-onelake.yml`. A skipped engine module is not a pass.
Use the existing deployment Pester checks and applicable Bicep validation as well:
Python checks alone do not validate retained deployment artifacts.

For local reproduction from the repository root, use the selected development Python
environment with the pinned requirements and JDK 17. Example PowerShell commands
(instructions only; **not execution evidence**):

```powershell
python -m pytest src\pilots\fabric-onelake\validation src\pilots\fabric-onelake\notebooks\tests -v
Invoke-Pester -Path src\pilots\fabric-onelake\deploy -Output Detailed
```

The pytest directories include the engine module; confirm it actually executes.
Missing dependencies require restoring `requirements-dev.txt` in the chosen environment.
Windows Spark execution may additionally need a compatible Hadoop/winutils setup;
record the real toolchain or use the existing CI environment rather than count a skip
as success. Perform the applicable retained Bicep compilation separately with the
repository's established tooling. None of these commands substitutes for Fabric.
The deployment tests require Bicep on `PATH` or `BICEP_CLI_PATH` set to the absolute
compiler path. Set that prerequisite in the same PowerShell process that invokes
Pester; do not assume a compiler installed outside `PATH` will be discovered.
A missing-compiler failure is a setup failure, not a skipped or passing test.

Required coverage includes all canonical numeric fields and accepted/rejected Parquet
variants, persisted Delta types, precision/range/null behavior, incompatible targets
preserved on failure, replay, open/closed-month corrections, credits/fractions,
staging truncation, unchanged months, and the operator-controlled coverage/order/writer
cases. Also cover deterministic evidence selection/timestamps/ties, read failures,
boolean/failure-only diagnostic semantics, metadata addition on fresh/legacy tables,
and retirement/import inventories.

The UTC-month engine regression deliberately starts with the session time zone set
to `America/Los_Angeles` and checks that notebook 02 restores UTC before deriving
months. Its engine execution remains pending the native-runtime blocker; the test's
presence alone is not evidence of correct execution.

Notebook 00 supplies 36 deterministic synthetic rows across April–June 2025, two
scopes and two currencies, with charges, credits, `1e-18` fractions, optional nulls,
and all canonical Decimal fields. Its `numeric_variant` selects accepted decimal
input or deliberately rejected double input. Output derives from `OUTPUT_PATH`
(`Files/sample-focus` by default) with the variant suffix; separate JSON producer
expectations at `source_path + "_producer_expected"` use independent Python `Decimal`
grouped totals and tolerance 0. Preserve those expectations/configuration rather than
derive authoritative counts or totals from staging. See [generator setup](../README.md#synthetic-generator-parameters-and-expected-results).

Record exact commands, runtime/toolchain, pass/fail/skip counts, tested revision, and
evidence location after execution. Local Spark is not Fabric: OneLake paths/catalog,
SQL synchronization, report refresh/measures, live identity/access, and capacity
behavior require the [mandatory manual synthetic protocol](../README.md#required-validation-and-evidence).
Future optional live provisioning claims need rerun/idempotency/resource-identity
evidence; optional ADF claims need identity, parameters, job lifecycle, timeout,
failure and retry evidence. Static/mocked checks do not establish those behaviors.

## For roadmap consideration

These are conditional workstreams, not obligations in the first contribution. Each
needs an owner, requirement, permissions, budget, evidence location, and stop decision.

### Actual source integration and operating value

Verify real upstream stage/schema/semantic provenance, extraction/casts, dependencies,
complete snapshot acceptance, open/closed-month corrections, replay, recovery, and
full-cycle SQL/report financial parity. Scope any automatic RTI connector, export
hook, core hub deployment switch, or notebook chain separately. Leave existing RTI
consumers unchanged and document copy access control and consumer rollback.

Before sustained use, establish scheduling, alert routing, failure recovery,
retention/cleanup and operational ownership. Validate source/backfill horizon,
serving retention and report windows independently of Delta time travel. A MACC
period is customer-specific; the existing `macc-consumption-vs-commitment.kql`
contains unresolved commitment-semantics/data-gap notes and is not a new Spark
calculation contract.

Select volume, history, concurrency, freshness and latency acceptance targets.
Compare RTI/KQL, Eventhouse-managed OneLake access and this copy with matched measures,
scopes, workloads, capacity/cache conditions, and extraction/storage/compute/support
costs. Evaluate upstream KQL aggregation/materialized views before Spark summaries;
any summary needs explicit grain, currency, and restatement semantics. Capacity
chargeback can inform attribution, but an app-owned model is not a supported
integration dependency. Retire the extra copy if it adds no measured value.

### Direct Lake adoption and layout redesign

Choose Direct Lake mode explicitly and test the actual model, security/identity,
relationships, uniqueness, framing, cold-query latency and memory at intended scale.
Direct Lake on SQL and on OneLake have different fallback semantics; there is no
blanket fallback multiplier or license guarantee. Validate maintenance/framing
interaction; notebook 04 cannot authorize the model.

Evaluate runtime-supported liquid clustering, auto-compaction, adaptive sizing,
partitioning and V-Order only with measured predicates and write/query costs.
Changing layout/cadence requires coordinated contract, compatibility, metrics, and
SLA tests. A maintained per-SKU lookup might help later, but must distinguish platform
limits, mode differences, and workload tuning rather than freezing stale numbers.

### Packaging, networking, and graduation

Evaluate Fabric-native lifecycle/package options rather than promising a particular
wheel, deployment tool, or complete chain now. Private networking remains rejected
by current preflight; workspace identity/trusted workspace access/managed private
endpoints need separate current-prerequisite and end-to-end validation, not a claim
that Fabric cannot support them.

The [graduation criteria](../README.md#non-goals-and-graduation) still require real
full-cycle corrections, measured Direct Lake and production policy, intended-cloud
evidence, comparative total economics, build/packaging, and ownership/support
decisions. A synthetic correction or passing diagnostic is not graduation.
